# Ecosystem coordination posture

**State:** adopted doctrine; candidates under evaluation

Harriet should approach upstream communities with concrete profiles, test fixtures, bug reports, and patches. **PARTNER** means active coordination after mutual acknowledgement. Every project named here is currently a candidate, not a formal partner, unless a later decision record links evidence from both parties.

Reticulum, LXMF, RNode, Sideband, Haven MANET, MeshCore, Meshtastic, delay-tolerant networking implementations, Babel, OpenWrt, LibreMesh, Freifunk Gluon, and AREDN retain independent identities and governance. Harriet does not speak for, endorse, or imply endorsement by them. Compatibility claims require a named Harriet-owned profile or adapter, versioned fixtures, test results, and an explicit maturity state.

[Bitchat](../integrations/bitchat.md) is tracked as a native parallel proximity payload. It has no verified Harriet adapter or partnership.

Maintain a distinction between upstream results and Harriet qualification. [MeshSat](https://github.com/meshsat/meshsat) is a reference for multi-bearer dispatch, persistence, and typed outcomes. [MeshForge](https://github.com/Nursedude/meshforge/blob/main/docs/GATEWAY_DEPLOYMENT.md) reports adjacent gateway work. The [MeshCore Reticulum-backhaul discussion](https://github.com/meshcore-dev/MeshCore/discussions/1736) is a proposal. Each would need profile-specific evidence for authorized representations, opaque custody, and exact-object delivery. These observations establish no adoption or upstream coordination.

Current project status, interfaces, naming, governance, and licensing must be externally verified before outreach or implementation. No such review is asserted by this page.
